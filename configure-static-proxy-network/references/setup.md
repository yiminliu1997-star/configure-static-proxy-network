# 从控制台到可用环境

这是本次 Windows 配置经验整理，不是让用户逐条照抄的安装命令。实际执行细节、备份与回滚见 [reconcile.md](reconcile.md)，稳定参数见 [desired-state.json](desired-state.json)。本文件整理于2026-10-27；历史成功不代表新电脑已通过测试。

## 1. 分清三种地址和“直连”的含义

| 对象 | 本机基线 | 用途 |
|---|---|---|
| 固定出口IP | __PROXY_EXIT_IP__ | 目标网站在代理请求上看到的来源地址 |
| 代理接入点 | __PROXY_UPSTREAM_HOST__:__PROXY_UPSTREAM_PORT__ | 本机代理核心连接的入口，认证方式按提供商要求 |
| 本机代理 | 127.0.0.1:12460 | 浏览器、Claude和Code连接的本机监听端口 |

这里的“代理直连”表示电脑直接连接代理，不再通过樱花猫中转；仍使用代理，并非让应用绕过代理。购买的出口IP不是Windows网卡地址，也不能直接当作任意代理服务的接入地址。入口域名解析出的IP与固定出口不同，可能更新。

## 2. 从所选提供商取得接入参数

确认套餐提供固定出口，而不是轮换出口或仅有时效粘性会话。获取目标公网出口、入口主机和端口、协议（HTTP、HTTPS 或 SOCKS5）、认证方式、固定出口绑定方式、TLS 证书名称（如需）及来源 IP 白名单要求。入口与出口可能不同。

不要沿用其他提供商的用户名格式、端口规律、地区参数或会话标识。截图中截断或掩码的字段不能当作凭据。密码在目标电脑安全保存；不写入技能或聊天。

当前运行模板支持用户名密码认证的 HTTP/HTTPS/SOCKS5 上游。白名单免密、特殊认证、其他隧道协议或 IPv6 入口需要先适配模板并完成独立验证，不要生成假凭据。HTTPS 校验证书，不能关闭验证。SOCKS5 保留域名交给代理端解析；用实际查询测试确认。

## 3. 先盘点，再搭建独立本机代理

记录已有系统代理、PAC、用户及应用环境变量、樱花猫等进程、端口占用、应用路径、任务和网卡DNS。备份将改动的项，确认当前聊天依赖哪条线路。

选稳定运行目录，不依赖会随应用卸载或升级变化的MSIX缓存目录。本机为rootHint；新机可以重新选定。设置受限ACL，将代理凭据按本机当前用户安全加密保存。准备可信兼容的sing-box核心，模板不包含二进制或凭据。

按Control.ps1模板建立127.0.0.1:12460的mixed监听，唯一上游为代理。先配置校验，再启动、检查端口所有者，再明确指定该代理访问__PROXY_CHECK_URL__。必须得到约定出口，才能向后推进。不要停止现有健康代理来验证新配置；必要时用空闲临时端口。

## 4. 接入 Windows 与各应用

| 使用方 | 配置位置/机制 | 验证重点 |
|---|---|---|
| Edge、Chrome | Windows WinINet per-connection固定代理 | flags=3、代理12460、空PAC、关闭自动发现；现有浏览器实际刷新IP页 |
| 当前ChatGPT/Codex | 用户代理环境变量及本机使用的.codex/.env | 新进程与已有进程可能不同；网页能用不能证明桌面后端能用 |
| Claude Desktop | 实际应用配置中的egressProxyUrl | 按已应用profile修改，保留1p/3p模式和登录数据 |
| Claude Code | .claude/settings.json的env | HTTP_PROXY、HTTPS_PROXY、ALL_PROXY、NO_PROXY及远端DNS变量 |
| 第三方API路由器 | 每个HTTPS请求显式使用代理Agent | 不能只依赖系统代理或Node环境变量；核验实际上游请求 |

HTTP_PROXY、HTTPS_PROXY、ALL_PROXY均使用本机目标localProxy；HTTPS_PROXY的值使用http://表示连接本机HTTP CONNECT代理，不代表目标HTTPS内容被降为明文。NO_PROXY仅保留约定本地地址。

在确认环境变量生效前，不声称普通启动入口可用。需要应用重启时安排用户完成，不能终止当前管理聊天。专用快捷方式只是可选入口，不能替代完整代理配置。不要通过复制Cookie或登录令牌伪装旧设备。

## 5. 加入失败时禁止直连的保护

确认代理连通之后，为实际在用的Claude Desktop、Code、Edge、Chrome、专用router Node配置非loopback出站Block。保留localhost代理及本地API访问。模板规则按程序完整路径生效，应用升级后重新发现路径。

不要限制共享Node、主代理核心或当前ChatGPT/Codex主程序；ToDesk明确保持原状。这里不是整机VPN或所有进程的全局代理。代理断开时受保护程序应失败，而不是回退到其他出口。

## 6. 分阶段启用 DNS 保护

先让Code使用CLAUDE_CODE_PROXY_RESOLVES_HOSTS=1。建立独立DNS核心：目标域名通过本机代理访问远端DoH，只有__PROXY_UPSTREAM_HOST__用本地已验证入口记录，避免DNS与代理互相等待。

先在独立15353测试，成功后再启用127.0.0.1和::1的53/TCP+UDP监听，最后切换实际上网网卡DNS。不要先改网卡DNS再启动服务。记录原DNS及DHCP模式用于回滚。

应用防绕行与DNS端口保护分别核验。Edge关闭自带DoH是为了让它使用受保护系统DNS，上游仍为加密DoH；并不等于“DNS不加密”。不禁用整个系统IPv6，也不把“手动改成海外DNS”当成防泄漏完成。

## 7. 配置启动与系统代理自动恢复

四项任务为代理、DNS、Claude Model Router Watchdog、SystemProxyGuard。按reconcile.md的无窗口守护流程做S4U/Session 0预检，再配置登录触发、Limited、无限运行及失败重试。新电脑不能假定S4U能解密DPAPI凭据，预检失败时保留健康连接并报告阻塞。

健康核心不重启。任务接管已存在的核心/路由器时应等待现有进程，不能生成重复watchdog。SystemProxyGuard检测系统代理配置漂移并恢复；它不补救代理服务本身故障，也不替代防火墙。要主动更换代理，先停这个配置守护，避免相互覆盖。

## 8. 验收与交付

按reconcile.md的实际核验逐项执行，至少包含：精确出口、两个浏览器、Claude/Code及第三方API的实际请求、有效防火墙与版本覆盖、DNS正常/故障查询、受保护进程IPv4/IPv6直连失败、失效代理不回退、任务和心跳。

使用独立测试端口模拟故障，不切断主网络。不拿空抓包文件证明没有DNS流量。没有执行浏览器或登录后测试的项目标未验证；没有重启电脑就不能说重启已实测。

交付脱敏报告、备份目录和对应回滚入口。自动审计脚本的全部通过也不等于上述全部实际行为均已验证。

## 9. 在家里或新电脑重建

迁移技能和无秘密模板，重新发现用户/SID、程序版本、网卡及任务权限；重新安全保存代理凭据，不能直接复用旧机DPAPI文件。第三方提供商密钥单独安全配置，原业务路由器不在技能包内。

家庭宽带IP可以不同，正确经过同一代理出口的请求仍可显示同一出口IP。功能相同的网络配置不等于同一设备身份；新登录会话、浏览器及系统信息仍可能被服务端识别，不能承诺规避设备识别或账号验证。校园网掉线通常导致请求失败，不能把未经现场验证的认证门户行为保证为绝对不泄漏。
