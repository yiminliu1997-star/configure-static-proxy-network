# 踩坑与排障索引

记录本次配置过程中的可复用经验。时间、版本、错误码是历史证据；不是每次出现同样现象都可直接套用同一原因。修复细节见 [reconcile.md](reconcile.md)，首次搭建见 [setup.md](setup.md)。

## 已观察到的问题

| 现象或坑 | 本次证据/原因 | 处理与验收 |
|---|---|---|
| 把出口IP当代理地址 | 控制台IP列表与Endpoints是不同字段 | 用完整接入点、端口、凭据；再核验实际出口 |
| 退出樱花猫后聊天断联 | 初期链路仍依赖旧本地代理或未刷新进程配置 | 使用独立核心及正确的12460；逐个检查应用配置，不仅看系统代理 |
| 浏览器可用，桌面端一直重连 | 浏览器与桌面后端的代理来源不同 | 检查用户环境、.codex/.env、已运行进程和实际后端连接；不要只改快捷方式 |
| Chrome、Edge同时完全断网，但聊天继续 | 2026-10-23实际连接flags=1（DIRECT），保存的ProxyEnable和地址仍看似正确；显式代理访问成功 | WinINet API恢复flags=3后用户确认两浏览器恢复、出口正确；加SystemProxyGuard。不要撤销防绕行来“修好上网” |
| 怀疑樱花猫关闭系统代理 | 它的退出报告显示proxy清理；没有可靠记录把具体注册表写入归因到它 | 只能称怀疑。用户要求停止追查；未启用额外注册表审计。Guard日志记录漂移，不记录写入者 |
| 启动守护未运行，但核心还在 | 曾见任务Ready、工作进程已结束，而代理/DNS/路由器核心继续存活 | 同时看任务、worker心跳和核心PID。修复时接管健康核心，不按名称或进程树全部杀掉 |
| 开机后冒终端，用户误关可能影响守护 | 后续配置已改为S4U非交互Session 0；仅Hidden参数不足以保证无桌面窗口 | 按无窗口流程先验证凭据、入口、网络和HKCU，再迁移；不要回退Interactive或重试被应用控制阻止的自编译启动器 |
| Microsoft网站失败导致启动代理设置失败 | 旧Test-Exit额外要求www.microsoft.com成功 | 已改为HTTPS精确出口检查；目标站点策略失败不应阻止系统代理开启 |
| Outlook打不开 | 2026-10-23经Proxy访问两个Outlook入口返回417，login.live.com连接重置；DNS及出口正常 | 单独处理目标站点限制/兼容性。417含微软响应标识，不能仅凭错误码认定Proxy拦截；不自动换IP或开放直连 |
| Node设置了环境变量仍不能证明走代理 | 业务路由器需要显式HTTPS Agent代理配置 | 检查各上游请求使用同一Agent，/proxy-check与实际提供商请求分别验证 |
| router更新/迁移误伤当前聊天 | 共享Node同时服务其他任务；按node.exe全局拦截或终止会扩大范围 | 复制可信Node至专用路径，仅限制专用router Node；watchdog用process.execPath |
| 一个域名或IP检测成功，被当作所有流量成功 | IP检测只证明该次请求，官方登录和第三方API也不是同一路业务 | 分别核验浏览器登录跳转、Desktop、Code、router；权限不足/未登录标未验证 |
| HTTP401/404被当网络故障 | 无效测试密钥到达官方API可返回401；某第三方count_tokens不支持可返回404 | 区分鉴权/端点能力与网络。最小有效业务请求才能证明业务成功 |
| 更改DNS后代理与解析互相等待 | 主代理要解析__PROXY_UPSTREAM_HOST__，系统DNS又要通过主代理访问DoH | 保留动态验证的本地入口pins；先测试独立DNS，再切换网卡 |
| pins能TCP/TLS连接但不一定是正确出口 | 可达入口不等于目标账户的固定出口验证 | 用独立临时代理和本机凭据核验精确出口；失败保留最后可用pins |
| 更新bootstrap.json被当作立即生效 | 历史DNS worker新pins在下次核心启动加载 | 比较运行配置与文件；不为更新强制重启健康服务 |
| “空抓包=没有DNS泄漏” | 本机PktMon曾导出空ETL/PCAP，但NIC计数器可工作 | 新查询负载下看物理NIC出站计数，做__PROXY_UPSTREAM_PORT__流量正对照；区分入站广播 |
| Block Any再Allow代理仍不能访问 | Windows显式Block覆盖Allow | 只Block非loopback地址，保留本机代理；分别检查IPv4/IPv6及所有profile |
| 应用升级后规则仍显示存在 | 程序规则绑定旧完整路径，名称中的旧版本号不代表当前覆盖 | 发现实际安装/运行路径并检查ApplicationFilter；新路径通过后再清理旧规则 |
| 注册表数值或任务状态被误读 | PowerShell对象转JSON可能把枚举显示为数字；Session 0命令行读取可能需要管理员权限 | 显式枚举名及ActiveStore核验；无权限记unknown，不当失败或成功 |
| PowerShell5中文路径/JSON乱码 | UTF8无BOM源脚本及默认读取编码存在差异 | JSON显式-Encoding UTF8；含中文的PS5脚本保存UTF8 BOM；参数正确引用 |
| ToDesk仍显示真实IP | ToDesk未纳入应用出口限制，且用户明确不修改 | 不把其真实IP等同Claude泄漏，不擅自加入限制；说明不是整机全流量保护 |

## 不能过度承诺的边界

- 当前ChatGPT/Codex主程序与共享Node未加入同样的非loopback阻断。它们配置代理不等于具备与Claude/浏览器一样的强制防绕行。
- “断代理后请求失败”的独立测试不等于真实校园网断线、门户认证、整机重启全都已验证。不要给出没有依据的泄漏概率。
- S4U在本机的成功不保证新机或未登录场景能访问加密凭据。不要改用明文存储或降低安全设置解决预检失败。
- 相同Proxy出口并不能让新电脑看起来必然是同一设备；不复制登录Cookie作为网络迁移步骤。
- 本机目标IP及端口是用户已有套餐，不适用于其他账户；迁移到另一套餐必须替换所有相关校验值并重新测试。
- 不包含密码、API Key、登录数据或核心二进制的skill不是整机镜像。依赖丢失时说明缺少什么，不假装能凭技能恢复全部账户数据。

## 快速定位顺序

1. **所有浏览器不通**：先查12460监听者、明确指定代理的IP请求和DNS；若代理成功则查WinINet实际flags/PAC/扩展/启动参数及有效防火墙，不先拆保护。
2. **只有一个站点不通**：检查状态码、TLS/连接错误及当前供应商限制，不反复改DNS或系统代理。
3. **仅桌面/Code不通**：检查应用自己的代理、启动时继承环境和后端请求；用网页成功作对照而非结论。
4. **重启或关窗口后不通**：检查四项任务、Session 0、日志和心跳；确认代理凭据可解密、入口pins可用。
5. **需要主动换代理**：先暂停SystemProxyGuard；用户要求固定出口时不能自行回退其他代理或本地公网IP。

## 需要重新核对的外部依据

目标站点限制随提供商、套餐和时间变化。查所选提供商的当前官方文档；不能仅凭417或403归因。保留目标域名、时间、状态码与出口供用户联系支持，不自动切换出口或代发消息。

[Claude活跃会话说明](https://support.claude.com/en/articles/13124001-managing-your-active-sessions)及[隐私政策](https://www.anthropic.com/legal/privacy)支持“同一出口不等于同一设备”的边界；不推断官方未公开的具体设备识别算法或封号阈值。
